# MAPS-1/2/3：知识、状态、动作、反馈

> 规范版本：0.1（Draft）
> 关键词 MUST / SHOULD / MAY 按 RFC 2119 理解。
> 本文承接 [`mod-card.md`](mod-card.md)：MAPS-0 让 Agent 知道"有你"，本文让 Agent 知道"怎么玩"。

## 1. 总则

一个模组"对 Agent 可玩"，至少要让 Agent 能完成四步：

1. **查**：知道这台机器/这件物品能做什么（知识）；
2. **看**：知道它现在是什么状态（状态）；
3. **做**：能做语义动作，而不是点像素（动作）；
4. **懂**：失败知道为什么，长活知道进度（反馈）。

四步缺一不可。只给配方、只给 GUI、只给原始 NBT，都不算可玩。

## 2. MAPS-1：知识（Knowledge）

### 2.1 MUST

- 每一种**会改变世界**的配方类型 MUST 能回答：产出什么、需要什么、在什么机器/工序里做。
- 有机器/多方块结构的模组 MUST 提供**机器映射**：配方类型 → 需要的方块/结构/热量/速度/空间。
- 有工序的模组 MUST 保留**顺序**（如 `sequence`、`loops`），不能只给一个无序集合。
- 配方中的**概率、副产物、流体量、容器返还、工具要求** MUST 能被读到；读不到就明确说"不知道"，不能猜。
- 知识 MUST 能被 Agent 按至少一种方式查询：按产出、按输入、或按机器。
- 知识中的 id MUST 稳定（命名空间 + 路径），名字 SHOULD 使用主人语言。

### 2.2 SHOULD

- 提供"我现在背包里这些能做什么"的查询。
- 提供结构化教学：步骤、方块、位置、顺序、说明（Ponder 的文本/步骤，而不是只有动画）。
- 提供典型任务示例与常见失败。
- 提供 `uses`（这件东西能拿来做什么）与 `info`（说明），而不只是 `recipes`。

### 2.3 MAY

- 提供机器/产线的成本与时间估算。
- 提供配方版本与来源（§ 数据包、模组 id、整合包覆盖）。

## 3. MAPS-2：状态（State）

### 3.1 MUST

- 每一类机器/网络/结构 MUST 有一个**只读快照**，不要求打开 GUI。
- 快照 MUST 包含：
  - 状态：`idle` / `running` / `blocked` / `done` / `error`；
  - 进度：`progress_percent` 或 `seconds_left` / `eta`；
  - 内容：输入/输出/燃料/容器，按**角色**区分；
  - 原因：`blocked` 必须是结构化原因（`code` + `detail` + `hint`），不能只有 `false`。
- 字段名 MUST 稳定、`snake_case`、英文；单位 MUST 写进字段名或文档（`_mb`、`_ticks`、`_percent`、`_rpm`、`_su`、`_fe`）。
- 状态 MUST 是服务端权威的；客户端只读缓存不得当作事实。
- 状态读取 MUST 是只读的：不改世界、不动身体、不消耗物品。

### 3.2 SHOULD

- 批量读取：一次拿一片/一张网络，而不是逐格 N+1。
- 提供 `next_step`：下一步该做什么（放什么、修什么、等多久）。
- 提供 `members` / `network` / `anchor` 这类结构标识，让 Agent 能把单格状态拼成系统。
- 对 Contraption、列车、物流这类移动/长状态，提供**按锚点/网络**的快照，而不只是按方块坐标。

### 3.3 MAY

- 提供历史/趋势（最近 N 秒的产出、停机次数）。
- 提供状态变更事件（见 §5）。

## 4. MAPS-2：动作（Actions）

### 4.1 MUST

- **每个会改变世界的 GUI 操作 MUST 有等价的语义动作**；不能要求 Agent 记槽位坐标或点按钮。
- 动作参数 MUST 用语义值：物品 id/标签、数量、流体量、角色、坐标/锚点、枚举模式；不能只用槽位编号（槽位编号可以作为可选覆盖）。
- 动作 MUST 先校验：能不能放、够不够、会不会过载、有没有权限；校验失败不产生副作用。
- 动作 MUST 返回**结果**与**类型化失败码**；不能只回 `accepted`/`failed`。
- 动作 MUST 是幂等的：重复调用安全；不能重复消耗材料或重复放置。
- 写操作 MUST 经宿主/模组的权限层裁决；名片里的 `permissions` 不是放行凭证。

### 4.2 SHOULD

- 提供 `dry_run` / 预测：会消耗什么、会产出什么、要多久、会不会过载。
- 长活返回任务/作业句柄：进度、取消、部分结果。
- 动作完成后返回可验证的状态（或让 Agent 能立刻 `status` 复核）。
- 失败码带 `hint`：下一步该做什么。

### 4.3 MAY

- 提供事务/回滚（能撤销的才撤销，不能就明确说）。
- 提供批量动作（一次填满一组机器、一次发一班列车）。

## 5. MAPS-3：反馈与规划（Feedback & Planning）

### 5.1 MUST

- 长活 MUST 有进度与终态：`started` / `progress` / `done` / `failed` / `cancelled` / `stalled`。
- 失败 MUST 说明：哪一步、什么原因、怎么修。
- 事件/状态 MUST 能被轮询或订阅；不能只写日志。

### 5.2 SHOULD

- 提供试算/计划：给定目标与速率，返回机器链、材料、时间、空间、动力/热量/速度需求、瓶颈。
- 提供事件流：`machine_started`、`machine_done`、`overstressed`、`train_arrived`、`contraption_moved`。
- 提供权限/审计：谁在什么时候让哪台机器做了什么。

### 5.3 MAY

- 提供失败注入/沙盒（评测用）。
- 提供产线优化建议（减少 SU、提高吞吐）。

## 6. 发现与集成

- 名片（MAPS-0）MUST 声明 `requires_client`、`permissions`、`limitations`。
- 客户端专属能力（JEI、Ponder、地图）MUST 标明；服务端 MUST 只把它当可选知识，不作为权威状态。
- 宿主 SHOULD 在运行时把名片入口与真实注册表对一遍；缺失的入口标为不可用。
- 模组 SHOULD 在目标模组不在时零加载、零报错；不要硬绑。

## 7. 性能与安全

- 状态读取 SHOULD 在主线程做短小只读工作；长活 SHOULD 异步、按刻推进、可取消。
- 回答者/快照 MUST NOT 在读取时执行慢查询、网络请求或世界写入。
- 返回 MUST 有大小上限；大结果分批或摘要。
- 权限 MUST 在执行时裁决，不能只靠调用方声明。
- 破坏性/跨领地/移动方块的动作 MUST 有同意或审计。

## 8. 符合检查表

### MAPS-1

- [ ] 配方类型能回答"产出/输入/机器"
- [ ] 有机器映射
- [ ] 保留工序顺序
- [ ] 概率/副产物/流体/工具/容器返还可见
- [ ] 有至少一种查询方式
- [ ] id 稳定、名字本地化

### MAPS-2

- [ ] 每类机器/网络有只读快照
- [ ] 快照含状态/进度/内容/结构化原因
- [ ] 字段 snake_case、单位明确
- [ ] 每个 GUI 操作有语义动作
- [ ] 动作先校验、幂等、返回类型化失败码
- [ ] 动作经权限层

### MAPS-3

- [ ] 长活有进度与终态
- [ ] 失败说明哪一步/为什么/怎么修
- [ ] 有事件或可轮询状态
- [ ] 有试算/计划（理想）
- [ ] 有权限/审计
